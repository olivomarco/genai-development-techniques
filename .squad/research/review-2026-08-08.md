## Blocking findings

### B1 — `overview.md` lines 120–121: corrupted spectrum cell

The HVE box in the complexity spectrum now reads:

```
││RPI +    │
││RPI +    │
││+ govern │
```

The second line previously carried `49 agents`. Removing the stale count left a duplicated `RPI +` and destroyed the descriptor.

**Correction:** replace line 121's HVE cell content `RPI +` with a non-duplicated descriptor that fits the fixed 9-character field, for example `agents   `. Verify the box borders still align in the rendered code block.

### B2 — `techniques/context-engineering.md` line 152: stale HVE instruction count

> "HVE implements context engineering through 102 instruction files, the RPI phased workflow, and constraint-based governance."

`techniques/hve.md` was corrected this pass to 80 `*.instructions.md` files observed on `main`, and every other `102` reference was removed. This is now the only surviving instance and it directly contradicts the corrected page.

**Correction:** remove the count, or restate as "repository-level instruction collections" without a figure. Do not substitute `80` here without also repeating the repo-tree-versus-release qualifier that `hve.md` carries.

### B3 — `techniques/squad.md` line 128 and `techniques/spec-kit.md` line 57: GSD described as Claude Code-native

- `squad.md:128` — "GSD is lighter and Claude Code-native; Squad is heavier and Copilot-native."
- `spec-kit.md:57` — "Unlike GSD (Claude Code-native) or Squad (Copilot-native), Spec Kit is designed to work across AI coding tools."

Both contradict the corrections made elsewhere in this same diff: `gsd.md` flipped Copilot, Cursor, and Windsurf from ❌/⚠️ to documented installer targets, and `choosing-your-approach.md` changed GSD's lock-in row to "Multi-runtime installer." Leaving these two lines makes the site self-contradicting on the single highest-priority fact of the refresh.

**Correction:** in both lines, replace "Claude Code-native" with wording consistent with the corrected GSD position, for example "GSD documents multiple installer targets with Claude Code as its deepest integration."

The following describe the archived `gsd-build/get-shit-done` product and are asserted as current GSD Core behavior. Trinity's ledger verifies only the five-step loop, the entry commands, the installer target list, npm packaging, and repository metadata — §8 item 2 explicitly records GSD Core's per-runtime feature depth as **not verified**.

| 59 | "XML Prompt Formatting. GSD uses XML-structured prompts" |
| 83 | "Quick Mode … Brownfield Support … Workstreams … Multi-Project Workspaces" |

**Correction:** for each item, either (a) obtain Trinity verification against the `open-gsd/gsd-core` repository and re-assert with a source, or (b) mark it explicitly as archived-era behavior not re-verified after the migration, matching the treatment already applied to community ports at line 122. **Correction:** add a single line above or below the Spec-Driven Development table, for example: "Star counts are snapshots observed on August 8, 2026 and are awareness signals, not adoption evidence." The GSD footnote can then reference it rather than standing alone.
